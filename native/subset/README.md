# Subset (macOS)

Subset is the manager app for Subset on the Mac: a menu bar app that will show which Subset apps are installed and install or update them from the same catalog feed, receipts and verification rules as the `subset` command ([SET-244](https://linear.app/21n/issue/SET-244)). It is a Subset capability in the `planned` state.

This folder holds its app shell ([SET-245](https://linear.app/21n/issue/SET-245)): a menu bar item whose menu opens an empty main window, a testable `SubsetCore` package, a generated Xcode project, macOS CI, and the release config that gives `macos/subset` signed betas. Listing the catalog's apps and the installed ones ([SET-246](https://linear.app/21n/issue/SET-246)) and installing and updating them ([SET-247](https://linear.app/21n/issue/SET-247)) come next; the shell reads no feed, makes no network connection, and installs nothing.

## Capability boundary

**User outcome:** see which Subset apps are on this Mac, and install or update them without a terminal.

**Sources of truth** (none read by the shell yet):

| Data | Source | Issue |
| --- | --- | --- |
| What Subset ships | The catalog feed, `https://subset.21n.dev/catalog/v1.json` (`SUBSET_CATALOG_URL` overrides it) | SET-246 |
| What is installed | Apps at the top level of `/Applications` and `~/Applications`, by bundle ID, and each app's own `Info.plist`; receipts are advisory | SET-246 |

**Explicit operations**

| Operation | Kind | State |
| --- | --- | --- |
| Open Subset (⌘O), About Subset, Quit Subset (⌘Q) from the menu bar item | App shell | Implemented (SET-245) |
| List catalog apps and installed apps | Read | Not started (SET-246) |
| Install or update an app | Write | Not started (SET-247) |

The menu is built from `MenuCommand` in `SubsetCore`, so the menu and its tests share one list.

The bundle ID is declared in `SubsetCore` (`SubsetIdentity.bundleID`), `macos-release.json`, and the generated project; `SubsetIdentityTests` checks they agree, and that `MacApp/Info.plist` sets `LSUIElement` and takes its identifier, version and minimum macOS from the project. CI checks the built Release app's `Info.plist` too.

The app is a SwiftUI `App`: a `MenuBarExtra` (the first scene, so launching shows only the menu bar item) and a `Window` scene that **Open Subset** opens. It runs with the hardened runtime and has no App Sandbox; `MacApp/Subset.entitlements` is intentionally empty. There is no app icon yet.

## Build and test

Requires macOS 14 or later. The package builds and tests with Command Line Tools or Xcode 26:

```sh
swift test --package-path native/subset
swift run --package-path native/subset Subset   # unbundled executable, for quick local runs
```

`Subset.xcodeproj` is generated by `ProjectGenerator.rb` (xcodeproj 1.27) from the same sources: the static `SubsetCore` library, the `Subset` app, and the `SubsetCoreTests` bundle, which the app does not host. Regenerate it after adding or removing a source file; generation is reproducible, and CI fails if the committed project differs. Regenerating replaces only `project.pbxproj` and the shared `Subset` scheme, so breakpoints, personal schemes and workspace state in `xcuserdata` stay, and a failed or interrupted regeneration puts the previous files back; `Tests/project-generator.sh` checks that. The generator needs exactly xcodeproj 1.27.0:

```sh
gem install --user-install xcodeproj -v 1.27.0
cd native/subset
ruby ProjectGenerator.rb
xcodebuild -project Subset.xcodeproj -scheme Subset -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO build test
```

`.github/workflows/subset-macos.yml` runs on macOS 26 for changes here: package tests, the generated-project check, an unsigned Debug `xcodebuild build test`, an unsigned Release build, and the check of the built app's `Info.plist`.

`macos-release.json` describes the app for `scripts/release-macos.mjs` (see [docs/macos-release.md](../../docs/macos-release.md)), so the **Beta builds** workflow builds `macos/subset` betas, tagged `macos/subset/v<version>-beta.<n>`. Locally, `node scripts/release-macos.mjs subset --archive-only` archives the app without signing credentials.
