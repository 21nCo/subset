# M Graph macOS capture spike (SET-4)

This is a local macOS development app that reads the foreground application's Accessibility tree when Capture Foreground is selected or a CLI capture is separately confirmed in the app's five-second dialog. The user can start it from Finder or `open MGraphCapture.app`; it appears in the menu bar. `Request Accessibility Access`, `Capture Foreground`, and `Quit M Graph` are its complete menu operations. It keeps no history, makes no network requests, and does not include graph inference. The CLI commands `status`, `request-access`, and `capture` are for repeatable native checks. `capture` requires a fresh local approval, pins the foreground process seen before that approval, and writes the result to stdout, so redirect it only to a private temporary file. A launch without approval reports `readFailed` with no text. There is no catalog download or public release.

The native target owns permission checks, foreground app selection, AX traversal, source identity, and the menu. No web host or product adapter consumes it yet. Source identity includes the app name, bundle ID, process ID, window title when exposed, and document URL when exposed. Each JSON result includes an observation time and a state. The collector bounds traversal to 600 queued elements, depth 12, 6,000 output text characters, and a four-second monotonic whole-operation deadline. Child arrays are counted and read by bounded AX ranges; an oversized array fails closed. Text normalization stops at the output budget. AX messaging has a 250 ms per-element timeout. macOS has no bounded read API for every scalar AX string: Chrome static text on this test host returns neither a useful character count nor a ranged string, so that provider reply is length-checked immediately after it arrives. This limits processing and returned text, but cannot cap the provider's allocation before its reply. A separate process with a memory limit would be needed for that stronger guarantee. The menu dispatches traversal to one serial worker queue and stays responsive; its Capture operation stays disabled until a cancelled or completed worker drains. The CLI waits at most four seconds after approval. A late or queued result is discarded. Both paths recheck permission, deadline, and foreground process identity before returning text. The worker requires `AXFocusedWindow` before and after traversal; `AXWindows` order and the app root are not foreground evidence. It compares the focused AX window, title, document, focused element, selected tabs, and web areas across traversal, then checks two subsequent text snapshots including one after the final source check. Missing focus, changed source metadata, changed text, or failed confirmation returns `readFailed` with no partial text or stale window metadata. The extra reads can cause a volatile page to fail closed or reach the deadline; this spike makes no promise of capturing continuously changing content. Empty accessible trees report `unsupportedApplication`. Secure/password roles and elements whose role cannot be read are skipped before their values are accessed.

## Build and native checks

Requires macOS 14+, Xcode command-line tools for the build, full Xcode for `swift test`, and Python 3 for the checks. Select Xcode with `DEVELOPER_DIR` if Command Line Tools is the active developer directory. From the repository root:

```sh
swift test --package-path native/mgraph
python3 -m unittest discover -s native/mgraph -p 'test_*.py' -v
MGRAPH_SIGN_IDENTITY='Apple Development: YOUR NAME (TEAM)' native/mgraph/build-app.sh
native/mgraph/check-native.py --expect-state available
native/mgraph/fixture-matrix.py
python3 native/mgraph/check-menu.py
```

Without `MGRAPH_SIGN_IDENTITY`, `build-app.sh` makes an ad hoc signed local bundle. The source-host check used an Apple Development identity; the destination-host check below uses a Developer ID Application identity. Both use hardened runtime. The bundle contains a declared `AppIcon.icns` for recognition in the Accessibility permission list. `codesign --verify --deep --strict` verifies the signature. `otool -L` and `check-native.py` reject non-system dynamic dependencies; Swift uses the runtime in `/usr/lib/swift`, so no separately installed Swift, Python, or Node runtime is needed to launch the app. Neither bundle is notarized and Gatekeeper rejected both development builds. No app sandbox entitlement is supplied; sandboxed AX behavior remains unverified. This is a viable local development packaging route, not a public download. Notarization, a fresh-Mac launch, and release distribution remain unverified. Apple requires a [Developer ID certificate and hardened runtime for notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

`check-native.py` launches the actual bundle through LaunchServices. This matters because invoking its executable from a terminal can inherit the terminal's Accessibility grant and report a misleading result. The check validates the signature, icon and linked libraries, reads bundled permission state, verifies startup/shutdown, rejects an unapproved CLI capture with zero text, then approves one foreground capture through System Events. Pass `--expect-state available` or `--expect-state permissionRequired` to make a grant or denial assertion; `available` also requires a readable foreground window and nonempty text from that approved capture. A foreground app with no open window correctly fails that strict assertion. `fixture-matrix.py` opens nonsensitive local fixtures in TextEdit, Safari, Chrome, and Firefox; it confirms each CLI capture in that exact owned bundle process, requires the fixture body and matching bundle ID in all four apps, and reports only text length, source identity, and fixture matches. It deliberately does not print captured page text. Before capture or close, both fixture scripts raise a uniquely titled window from the app’s AXWindows list and confirm AXFocusedWindow; browser selection inspects AX descendants for the fixture tab before pressing it and leaves other tab selections alone. The close path sends Command-W only after that check and polls AXWindows plus browser AX descendants for the unique fixture tab's disappearance. Chrome does not expose hidden tabs in AX descendants on this host, so its fixture adapter also uses Chrome's scriptable tab titles to select or close only the uniquely titled tab and verify its absence; the test runner needs Chrome Automation access. A fixture in an older browser tab that cannot be selected safely is reported as a focus or cleanup failure. The scripts delete their private result files. Each LaunchServices check tags its process with an invocation UUID, records the discovered process's kernel path and birth time, and rechecks that identity before termination or menu automation. Cleanup has a five-second overall deadline; each `ps` lookup uses at most one second, and a stalled lookup does not turn a previously known live process into an empty result. Both UI scripts check System Events access before opening a fixture; denied access exits without creating a window. Foreground activation can race with other desktop automation; a mismatched source identity fails the matrix and should be rerun in a quiet session. `check-menu.py` verifies the real menu click, waits up to five seconds for the asynchronous alert with each read bounded by the remaining time, checks its text and Quit path, and polls until its TextEdit fixture window disappears. It also needs System Events automation access on the test Mac.

To repeat denial and revocation, run `tccutil reset Accessibility dev.subset.mgraph.capture`, then run `native/mgraph/check-native.py --expect-state permissionRequired`. The bundled `status` and `capture` operations must report `permissionRequired`, with no text. Choose `Request Accessibility Access` in the menu bar app and enable this bundle in System Settings > Privacy & Security > Accessibility, then repeat with `--expect-state available`. Reset only this bundle ID; this command removes its existing grant. Turn its System Settings switch off and repeat the denied check to test revocation, then restore the original setting. Each capture checks the current grant, so a revoked grant is reported on the next capture. `request-access` opens the OS permission route but cannot grant permission itself.

## Risk and contract map

| Boundary | Risk | Focused evidence |
| --- | --- | --- |
| Permission transitions | Terminal grant can mask bundle denial; reset or revocation between bundled status and capture can falsely pass or leak stale text | LaunchServices status/capture before grant, after grant, and after reset; capture state assertion across the grant-to-revoke transition; per-capture permission check |
| AX traversal | Empty or slow trees, failed role reads, protected fields, huge arrays or scalar values | Count plus bounded range reads for both child traversals; fail closed on oversized arrays or unreadable roles; four-second monotonic deadline, 250 ms AX calls, late-text, empty-tree, secure-role, large-normalization and app fixture checks. Scalar provider replies without AX range support remain a documented allocation limit. |
| Foreground source | Another app, same-process window, or browser tab can change during traversal; missing `AXFocusedWindow` can select a background window; unavailable or reused AX metadata can hide same-window navigation | Require focused window before and after each text read; PID, AX source fingerprint, and three text snapshots must agree; missing-focus and unavailable-metadata navigation tests; matrix rejects app mismatch |
| Packaging | External runtime, invalid signature, sandbox or Gatekeeper restriction | `codesign`, `otool`, bundle start/stop, `spctl` observation |
| CLI/UI operation | Invalid command, unapproved CLI launch, repeated capture, Request Access during capture, slow alert, failed fixture close, interruption or launcher timeout | Exit 64 on malformed command, per-invocation CLI prompt and five-second zero-text timeout, worker-drain gating, delayed/timeout/read-error alert tests, asynchronous menu capture and Quit smoke check, optimized-Python verdict test, injected timeout/SIGINT/SIGTERM and stalled-process-lookup cleanup tests |
| Fixture lifecycle | A background fixture can yield a wrong capture or Command-W can close an unrelated front window; partial opens or malformed capture output can hide the actual failure | Require the unique title in AXFocusedWindow before each capture or close; inspect browser tab labels without selecting unrelated tabs; Chrome scriptable tab identity handles hidden tabs omitted from AX; AXWindows and tab disappearance readback plus dropped-close tests; per-app failures and cleanup outcomes stay separate |

The operations are read-only except for the OS permission request. There is no retry loop or persistent background capture. AX calls run on a worker while the menu stays active. Capture data is ephemeral in the menu dialog or explicit CLI output; the integration scripts delete their private temporary result files. The current app has no persistence layer. macOS alone is supported; web/iOS do not have this cross-app permission model.
