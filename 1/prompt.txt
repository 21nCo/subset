<result>I found no documented, read-only way to get a Factory Droid account's remaining subscription quota. Droid's status line and hooks carry no quota or rate-limit fields, there is no `droid usage` command, and the public APIs that touch usage are org-admin or Enterprise-only. Synara is the one product I checked that shows Droid quota, and it does so by decrypting Droid's stored login and calling an undocumented Factory endpoint.

## 1. What Factory documents
Docs are at docs.factory.com; docs.factory.ai redirects there.

**Status line**
- Setting `statusLine` in `~/.factory/settings.json` takes `{ "command": string, "padding"?: number, "maxRows"?: number }` and is configured with `/statusline` ([settings](https://docs.factory.com/droid-cli/settings.md)).
- The docs don't list the JSON sent to the command on stdin. From the local binary, the fields are `session_id`, `transcript_path`, `session_settings_path`, `cwd`, `workspace.current_dir`, `model{id, display_name, reasoning_effort}`, `context{last_call_compaction_tokens, token_limit, adjusted_tokens, adjusted_limit, percentage, display}` and `version`.
- That is context-window use only, not quota. This differs from Claude Code, whose status line now receives `rate_limits`.

**Hooks**
- Every hook payload carries `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name` and optionally `message_id` ([hooks](https://docs.factory.com/harness/hooks.md)).
- None carries token, credit or quota data. The closest are `PreCompact.estimated_tokens` and `SessionEnd.session_duration_ms`.

**CLI**
- The slash commands are interactive only, with no `--json` output ([CLI reference](https://docs.factory.com/droid-cli/cli-reference.md)):
  - `/cost`: usage for the current session
  - `/stats [period]`: usage statistics
  - `/limits`: credit rate limits and overage preferences
  - `/billing`: billing settings
  - `/context`: context-window breakdown
- There is no `droid usage` subcommand. `droid exec -o json` and `droid doctor --json` exist but say nothing about quota.

**API** (base `https://api.factory.ai`, header `Authorization: Bearer fk-…`)
- `GET /api/v1/analytics/tokens` and `/users` are organization-wide and need the Manager or Owner role ([analytics](https://docs.factory.com/api-reference/analytics.md)).
- `GET /api/v1/analytics/cost/me/query` returns only the caller's own data, but only for "Enterprise organizations with Analytics enabled."
- `GET/PUT /api/v0/organization/usage/limits/{global,users}` read and set per-user credit caps set by an admin ([organization](https://docs.factory.com/api-reference/organization.md)). Response fields are not documented.
- No documented endpoint returns personal remaining quota, rolling-window percentage or reset time.
- API keys come from the org's API Keys settings, mainly for service accounts, which run as their own principal rather than as you ([identity and access](https://docs.factory.com/enterprise/identity-and-access.md)).

**Running several accounts**
- Documented: `FACTORY_API_KEY`, set per process.
- Undocumented, found in the binary: `FACTORY_HOME_OVERRIDE`, which replaces the home directory so Droid uses `&lt;override&gt;/.factory`. Note that the keychain item that holds the credential encryption key (service `"Factory CLI"`, account `auth-encryption-key`) is the same for every home.

**Plan and limit concepts** ([individual pricing](https://docs.factory.com/pricing/individuals.md))
- Plans: Pro $20/mo, Plus $100/mo (about 5× Pro usage), Max $200/mo (about 10×).
- Rate limits run in three independent rolling windows: 5-hour, 7-day and 30-day. Each starts at first use and resets after it elapses.
- Standard Usage is spent first and does not carry over month to month.
- Droid Core is a free open-weight model pool with its own rate limits, used after Standard Usage runs out.
- Extra Usage is prepaid USD credit ($10 minimum) that does not expire.
- The pricing page does not describe the allowance as tokens per month. A separate profile preference sends emails at 80% and 100% of the "monthly credit cap."

## 2. How the other products do it

**Synara** (MIT, [Emanuele-web04/synara](https://github.com/Emanuele-web04/synara)) does show Droid quota, in `apps/server/src/providerUsage/providers/droid.ts` and `droidCredentials.ts`:
- It decrypts `~/.factory/auth.v2.{loginkeychain,keyring,file}` with AES-256-GCM. The key comes from `/usr/bin/security` (service `"Factory CLI"`, account `auth-encryption-key-security-cli` or `auth-encryption-key`) or from `~/.factory/auth.v2.key`.
- It then calls the undocumented `GET https://api.factory.ai/api/billing/limits` (`api.eu.factory.ai` for EU) with `Authorization: Bearer &lt;accessToken&gt;` and `X-Factory-Org-Id`. If `FACTORY_API_KEY` is set, it first calls the undocumented `/api/cli/whoami` with `X-Factory-Whoami-Extended: true`.
- Fields it parses:
  - `limits.standard.{fiveHour,weekly,monthly}.{usedPercent,windowEnd}`
  - `limits.core.*`
  - `extraUsageBalanceCents`
  - `overagePreference`
  - `usesTokenRateLimitsBilling`
- The installed droid binary uses the same endpoint behind `/limits`; it also references `extraUsageAllowed` and `canManageOverage`.
- For multiple accounts it relies on a separate home directory or environment (`*_HOME`) per configured account, or `FACTORY_API_KEY`. Each result is keyed by home directory and a credential fingerprint.
- For Claude and Codex it calls `api.anthropic.com/api/oauth/usage` and `chatgpt.com/backend-api/wham/usage`, both undocumented.

**Orca** ([stablyai/orca](https://github.com/stablyai/orca)) does not track Droid usage. Its [usage-tracking docs](https://www.onorca.dev/docs/agents/usage-tracking) don't list Droid.
- `~/.orca/agent-hooks/droid-hook.sh` only forwards Droid hook events (Notification, PermissionRequest and so on) to `http://127.0.0.1:$ORCA_AGENT_HOOK_PORT/hook/droid`. If that fails, it writes them to a local spool file.
- `claude-statusline.sh` passes along Claude's documented status-line payload when it contains `rate_limits`, posting it with `configDir=$CLAUDE_CONFIG_DIR` to `/statusline/claude` at most once every 15 seconds.
- Orca also reads Claude's `.credentials.json` or keychain entry and calls `/api/oauth/usage`. For Codex it uses an RPC rate-limit probe plus `wham/usage`.
- It has an account switcher for Claude, Codex and others.

**Zeron** ([zeronsh/zeron](https://github.com/zeronsh/zeron)) has no Droid support. In `crates/engine/src/agent_accounts.rs` it reads Claude's `.credentials.json` under `CLAUDE_CONFIG_DIR` and Codex's `auth.json` under `CODEX_HOME`, then calls `api/oauth/usage` and `wham/usage`.

## 3. Local droid CLI
- `/opt/homebrew/bin/droid` reports version 0.236.0; it sits in the Homebrew cask folder labelled 0.74.0.
- Subcommands: `exec`, `daemon`, `search`, `update`, `mcp`, `plugin`, `computer` and `doctor` (`--json`, `--auth`). There is no usage or limits subcommand.
- `~/.factory/settings.json` has no `statusLine`. Its `hooks` already run Orca's `droid-hook.sh` and a Superset `notify.sh`.
- The login store exists as `~/.factory/auth.v2.loginkeychain`, `auth.v2.file`, `auth.v2.key` and `auth.encrypted`. I did not read any of them.

## Recommendation
- **Most legitimate documented source:** none gives personal remaining quota.
  - For Enterprise orgs, `GET /api/v1/analytics/cost/me/query` with the user's own `fk-` key returns only that user's spend.
  - Org Managers can read `organization/usage/limits/*`. Those are admin-set caps, not live quota.
  - The account boundary is the API key's principal and org. That means one key per account, kept in the OS credential store and supplied by the user.
- **Otherwise:** show Droid quota as "unavailable." The fallback is to send users to the `/limits` view or `app.factory.ai/settings/usage`. Hooks and the status line can add per-session context use, labelled as a local measurement.
- **Flag – reading another tool's stored login:** decrypting `~/.factory/auth.v2.*` with the "Factory CLI" keychain key, as Synara does, reads Droid's stored tokens. It breaks AGENTS.md's approved-credential rule.
- **Flag – undocumented endpoints:** `/api/billing/limits` and `/api/cli/whoami` are internal Droid calls. Calling them would need Factory's explicit approval.
- **Same flags for Claude and Codex:** `api/oauth/usage` and `wham/usage` are undocumented and need those tools' stored tokens. Claude's status-line `rate_limits`, which is documented and applies per `CLAUDE_CONFIG_DIR`, is the clean option there.
- **Unofficial multi-account isolation:** `FACTORY_HOME_OVERRIDE` is undocumented.
